Main-code communities, contextual layers and conversation profiles

Decentraland · Tension maps, version 1 · Generated 2026-10-13

What this analysis does

This system finds recurring associations between your main descriptor codes, groups the resulting network mathematically, and then adds contextual codes, technical depth and emotional composition. It uses the same rules, numerical settings and interface as the Decentraland version. The fixed map and gradual build are complementary ways of examining the same associations. Their communities are candidates for qualitative interpretation, rather than automatically established themes.

All 101 non-empty tension_content labels form the primary network. Tension labels are not automatically assigned the descriptor workbook's main/contextual classification. Their source spelling is retained, without new merging or recoding.

Your existing second-sheet descriptor classification supplies 117 contextual codes. The original descriptor sheet is copied to context_code_classification.xlsx for reproducibility and its message/topic counts are verified. These secondary descriptors are a separate magenta overlay. Even if a label appears in both fields, tension and descriptor nodes retain separate identities. Technical depth and emotion are further overlays. Only tension incidence determines communities, anchors and attraction.

Inputs and the meaning of a conversation

The source is decentraland_temporal_thematic_analysis_coded_thread_normalized_codes_normalized.json, containing 5,000 message records. Read semicolon-separated labels from tension_content, trim surrounding whitespace, and deduplicate labels within each message. Preserve code spelling and case. A code's total messages is the number of records carrying it, so a message with several codes contributes to several code totals.

There are 723 distinct non-empty thread_topic labels. Each label defines a topic group, and a code counts once per group regardless of repeated messages. These groups are the operational conversation unit used in the workbook and maps. Identical labels can pool separate exchanges, so the method does not identify independent chronological conversation episodes. The 91 messages without a named topic contribute to total message counts and the archive baseline, but not to the association network or named-topic profiles. 1617 records have no tension labels; they still contribute to a whole-topic profile when their topic is associated with that community.

Repeated JSON object fields use their final value, matching the earlier analysis and spreadsheet counts. The audit records repeated-field occurrences, source filenames and SHA-256 hashes. Emotion uses the decentraland entry of the existing Emotion category mapping.json, never the Decentraland mapping.

Interpreting the recorded labels

The field is not a guarantee that every label describes a conflict. Horizon Worlds includes positive_feedback in tension_content, and both datasets contain broader descriptive labels. They are preserved as coded rather than silently excluded or reassigned. These maps therefore represent tension-field labels. Review their meaning and source messages before describing every node as a substantive tension. No new synonym consolidation or semantic classification is imposed.

Connection weights and the three rules

Let f(A) be the number of topic groups containing code A and C(A,B) the number containing both A and B. The Jaccard weight is C(A,B) / [f(A) + f(B) - C(A,B)]. It measures relative topic overlap rather than raw message intensity. Jaccard remains the edge weight under all three rules.

1. Shared-topic overlap: retain a pair if it appears in at least the selected number of shared topic groups. It need not appear in the same message. This is the default broad association view.

2. BY-enriched overlap: also test whether overlap exceeds a fixed-coverage, uniform-topic reference model. Conditional on f(A), f(B) and the number of groups, use the one-sided hypergeometric tail P(X ≥ C). Correct all potentially eligible pair tests with the Benjamini–Yekutieli procedure, and retain adjusted p ≤ 0.05 plus the selected support threshold. The retained weight is still Jaccard. SciPy's hypergeometric documentation defines the tail distribution; its multiple-testing documentation describes BY and dependence.

3. Repeated message co-coding: require the two codes to occur together in a message in at least the selected number of distinct topic groups. Multiple co-coded messages in one group count as one supporting group. The weight is topic-level Jaccard, rather than message-level Jaccard. This is a stricter coding association than merely appearing somewhere in the same topic.

Support is adjustable between three groups, the default, and two for finer detail. At three, 33 tension labels have sufficient coverage to be potentially linked; at two, 47 do. Their fixed models are calculated separately. The corresponding BY test families contain 528 and 1,081 pairs, including zero-overlap pairs before applying the support filter. Enrichment edges at two need not be a superset of those at three because the correction family changes. One shared index of 47 codes supports both browser replays.

54 tension labels have coverage below two groups. Low recurrence does not establish low qualitative importance. A large total message count within one topic expresses concentrated coding intensity and cannot by itself establish cross-conversation corroboration.

The enrichment null does not preserve topic sizes, topic-specific coding richness, coding dependence or historical dependence. BY addresses multiple testing under valid marginal p-values; it cannot repair an inappropriate null model. Treat enrichment as a model-based diagnostic rather than proof of objectively existing themes. A degree-preserving bipartite permutation null would be a possible later sensitivity analysis. All three rules and both support levels are available for comparison.

Fixed communities and anchors

Partition each completed weighted tension graph with Leiden using the RB configuration/modularity objective at resolution 1. Run twenty seeds and select the partition with the highest weighted modularity Q. Traag, Waltman and van Eck (2019) describe Leiden's connected-community properties. Isolated codes receive no community membership and are never pooled into a false residual theme. Community numbers are ordered by group size and are local to each platform, connection rule and support setting.

The three anchors in a community have the greatest within-community weighted strength; topic coverage and code label break ties. Anchors describe central graph members and do not supply final interpretive theme names.

The fixed viewer offers community circles, all linked tension labels and a focused community. Circle area reflects member count; code-node area reflects topic coverage within display limits. Community centres are arranged for navigation, using a spaced grid when there are more than twelve communities. Internal positions use a weighted NetworkX spring layout with 400 iterations and a fixed seed. Inter-community display distance, contextual rings and outlier rings are visual arrangements, not additional statistical measurements. The screen draws up to 120 main edges in the all-code view and 180 in a focused view; every retained edge still enters the calculation and CSV files. Labels use collision checks and a limited overview budget; zoom or choose a code to inspect it precisely.

Gradual association build

Python supplies deduplicated topic incidence and message-pair evidence derived directly from tension_content. The browser admits one topic block at a time, updating code coverage, shared-topic counts, distinct-topic message-pair support and Jaccard weights. Blocks can be reproducibly shuffled or admitted in topic-label order. The browser uses the same support rules as the fixed calculation.

The default delay is 450 milliseconds per topic, about 5.4 minutes for this corpus before further settling. Speed can range from 0.10 to 1.50 seconds per topic. Play, Pause, One topic, Finish ingestion and Restart let you inspect the process. Node size grows with admitted topic coverage. Motion uses current weighted attraction, pair repulsion, a small centring force, damping and a displacement cap; the exact implementation is in viewer.js. Motion is a display mechanism and does not add evidence or change the edge counts.

Every twelve admitted topics, and after complete ingestion, a separate JavaScript multilevel Louvain-style optimiser updates live memberships. It starts from singletons, uses up to fifteen local-move passes per level, and aggregates for up to eight levels. A move compares weight into a group with node degree × group weighted volume / total weighted volume; aggregated self-loops preserve internal edge weight. Live colours use these memberships. The animation does not copy fixed Leiden memberships or pull nodes toward fixed community centres.

For the enriched replay, only final-archive BY-qualified edges are eligible; current admitted counts determine their growing weights. This declared gate uses full-archive information and avoids repeated partial-archive significance tests. The broad-overlap replay has no such future-information gate.

At full ingestion, edge counts and weights must equal the Python graph regardless of shuffle seed, because counting is commutative. Positions and partitions need not converge identically: the force layout has multiple possible configurations, and the live and fixed community algorithms differ. The completed replay reports live Q and adjusted Rand index against the fixed membership on reference-linked codes. Compare member labels and agreement indicators rather than matching community colours or numbers.

Shuffling is a procedural sensitivity view. It is not historical temporal thematic analysis. Topic-label order is also not chronology, and admitting a topic includes all its messages at once. A later temporal analysis should define timestamp windows and reconstruct comparable networks and profiles for those periods.

Contextual codes: how to show them

Open a community, then press Show contextual codes immediately above either map, or use the synchronised contextual checkbox in the top toolbar. The fixed map shows the completed associations immediately; an unstarted live map has no admitted main nodes yet. All supported contextual codes are listed beneath the profile, even when only ten satellites fit on the screen.

For a community, take the union of topics containing any member tension label. Compare that union with each contextual code's topic set using Jaccard. Retain context associations sharing at least the selected two or three groups; display the ten strongest as magenta satellites. An individual dashed link requires the same support between that contextual code and the corresponding tension label. Contextual codes exert no force, do not enter Leiden or the tension BY test family, and do not alter profiles. The live map's contextual overlay is final-archive information for the selected fixed community, rather than a partial-stream contextual estimate.

High-frequency outliers

Enable high-frequency outliers to inspect tension labels with no supported edges in the selected model and at least the chosen number of messages. The default floor is 100 messages, adjustable down to 25. These are descriptive inclusion criteria, not a statistical anomaly test. One-topic concerns can qualify. Codes that gain supported links in another model appear as ordinary main nodes there.

Hollow amber diamonds have area proportional to message count within display limits. Exploratory attachments compare an outlier's topics with each fixed community's topic union using shared-topic count and Jaccard; they require at least one shared topic. Dotted amber attachments do not confer community membership. Codes with no overlap remain inspectable without an attachment. At most twelve diamonds appear on screen, and the complete qualifying list is available; selecting a code brings it into view when relevant. Outliers never affect communities, anchors, attraction or profile membership. The overlay uses full-archive counts even during partial replay.

Technical depth

The default profile includes every message in the union of the community's associated named-topic groups, once within that community. A selector can restrict it to messages carrying a member tension label. Average valid manual technical_depth scores 0, 1 and 2; show their distribution, valid-score coverage, and the difference from the chosen overall comparator. The archive baseline is 0.384877, from 4,999 valid scores across 5,000 records. Invalid or out-of-scale values: 1. They are listed in the audit and excluded rather than silently recoded.

The alternative comparator uses only named-topic messages. Both technical depth and emotional bars use the selected profile scope and comparator. Means are message-weighted, so longer topics contribute more. Treat the ordinal levels' equal spacing as a descriptive convention. Differences from the overall mean are not significance-tested effects, particularly because a community profile is a subset of its comparator.

Profiles overlap across communities when a topic contains codes from several groups. Deduplication is within each community; the same message can contribute to several community profiles. Profiles therefore cannot be summed as disjoint archive portions, and similarity can reflect shared context.

Emotional composition

Use the existing manual Decentraland mapping and recorded typo aliases for the eleven categories: Violent, Dark humor, Shock, Disappointed, Skeptical, Annoyed, Defensive, Respectful, Light humor, Friendly, Excited. Split tags on semicolons, apply aliases, then deduplicate categories within a message. A message may belong to several categories. Divide each category's message count by the sum of the eleven category-message counts in the selected profile, matching the previous composition graphs. An empty mapped profile has undefined shares.

Neutral is outside these eleven shares. Preserve other categories that co-occur with neutral, and report neutral messages, unmapped tags, multiple-category messages and mapped coverage separately. Paired bars compare the community and selected baseline. There is no invented positive/negative balance score: categories such as shock, humour and defensiveness have ambiguous valence, and their order is not a validated psychological scale. These profiles describe coded expressions in captured messages.

Stability indicators and interpretation

For each of the six models, 50 bootstrap resamples draw the 723 topic groups with replacement, rebuild the network and rerun Leiden. Repeated groups contribute repeatedly. Enrichment recalculates its tails and BY adjustment within the same eligible-pair family for that support level. Pair co-assignment is conditional on both codes being present. Bootstrap ARI includes present reference-linked codes; reference isolates do not inflate agreement. Seed ARI compares the twenty reference-graph runs on linked codes. Fifty resamples provide an initial sensitivity diagnostic, not precise uncertainty intervals.

Weighted Q describes concentration of links relative to the configuration reference. Internal weight share is the proportion of a community's weighted connections staying inside; conductance measures its boundary weight relative to the smaller side's weighted volume. Resampled member-pair retention and outside-group co-assignment help distinguish stable local associations from unstable boundaries. ARI is 1 for matching partitions and near 0 around its chance reference. Resolution sensitivity at 0.5, 1 and 1.5 is saved in analysis.json. These indicators have no universal threshold establishing a substantive theme.

Use clusters to organise close reading: inspect tension messages, adjacent contextual codes, concentrated outliers, counterexamples and overlapping profiles. Develop an organising interpretation and then relate it to the theoretical framework. Mathematical association cannot replace that reflexive work; Braun and Clarke's guidance distinguishes analytic themes from mere topic summaries. Cross-platform comparisons should also consider differences in code vocabulary, granularity and conversational coverage.

Fullscreen and PNG exports

The fixed map, gradual build and profile each have Full screen and PNG controls in all three viewers. Escape exits fullscreen. A browser-denied native fullscreen request falls back to an expanded viewport. Zoom, fit, drag and local controls remain available. A larger fullscreen label budget still uses collision checks.

Map PNGs are rendered at 6,000 pixels wide with sufficient height for a complete numbered code key. They fit the selected view independently of screen pan and zoom. A fixed overview expands all linked nodes with the calculated internal community positions on a spaced print grid; a focused view exports that community. A live PNG captures its current evidence stage and positions without completing ingestion. Enabled focused contextual overlays include all supported contextual codes, beyond the ten-node screen limit, and enabled outliers include all relevant qualifying codes, beyond the twelve-node screen limit. No export changes counts, weights or memberships.

Unabridged on-map labels use collision checks and leaders. Crowded labels receive numbered references or side callouts. The full key supplies every exported code's label, type/community, message count and topic coverage. Label leaders are not network edges. Focused exports and native-resolution viewing improve legibility. Profile PNGs are 6,000 × 3,600 pixels, covering both depth and eleven-category composition. Browser memory can limit very large images; encoding failures are reported. Pixel resolution does not guarantee a physical print size or DPI.

Files and reproduction

START_HERE.html compares both maps offline. FIXED_MAP.html and ANIMATED_MAP.html open a single view and can switch to comparison. Each embeds the saved analysis and needs no server or internet. HTML files reflect a saved build rather than reading live Excel edits.

analysis.json contains provenance, counts, memberships, sparse edge lists, diagnostics, topic incidence, message excerpts and both profile scopes. classification_snapshot.json preserves your split. Three community/edge CSV pairs describe the default three-topic models; support2_ files describe two-topic models. METHOD_RESULTS reports the actual model sizes and diagnostics. Browser and data validation reports document checks of this build.

To rebuild, run build_analysis.py with --platform decentraland or --platform horizon-worlds, --root pointing to the PhD workspace and --bootstrap 50. Each platform retains its contextual descriptor workbook; --workbook can supply another two-sheet descriptor classification. Tension labels always come directly from the normalized source's tension_content field. The emotion mapping is selected by platform. requirements.txt lists dependencies and the current workspace provides them in work/gravity_runtime. The base seed is 20261008, matching the descriptor maps. write_outputs.py --platform regenerates viewers and notes from saved analysis. The two platform folders and earlier descriptor maps remain separate.

The prevalence table reports each tension's absolute message count, distinct named topic count and proportions against the entire archive and all named topic groups. Rankings can use either measure. A label recurring in many topics is not necessarily present in every topic or continuous through calendar time. The CSV retains every label, including isolates.

The gradual map keeps the same topic-block replay as the descriptor system. It is an agent-inspired display of fixed manual assignments rather than a game with adaptive strategies or exclusive ownership of messages.
