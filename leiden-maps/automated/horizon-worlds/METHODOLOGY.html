Horizon Worlds: revised LLM descriptor communities

Built 29 October 2026 using the numerical procedure and offline viewer from the existing manual v3 Leiden maps.

Inputs and descriptor inclusion

The input is horizon_worlds_consolidated_REVISED.json, the revised consolidated LLM-coded JSON, with 5,000 records and 485 distinct descriptor labels. The older July LLM files are superseded for this analysis. Split descriptors on semicolons, trim whitespace and deduplicate labels within each message. Preserve exact descriptor spelling and case; no semantic merging, new LLM coding or manual code substitutions are performed. Repeated JSON keys follow the existing last-key-wins convention; occurrences are audited.

All LLM descriptor labels are main network candidates. The LLM sources have no supplied main/contextual classification, so a manual-code worksheet split is not transferred. The contextual controls remain in the exact manual v3 interface, but report zero contextual codes for these LLM datasets. This is the explicit classification difference from the manual maps; broad interaction labels can therefore influence the LLM graph. Exact source label sets and message counts are verified. Labels without supported links remain searchable and are not assigned to a community.

Grouping and connection rules

Use each distinct nonempty complete thread_topic string as a topic-label group, exactly as in the manual maps. There are 720 groups; 45 messages have an empty topic and do not enter topic-level incidence. They remain in archive counts, profiles of the entire archive and the evidence inspector. 689 messages have no descriptors. Semicolons inside a thread_topic label are retained; those labels are not split into additional groups. Each code counts once per group. These revised labels incorporate episode IDs, but the analysis still uses primary thread_topic assignments and does not reconstruct secondary episode membership or uncaptured Discord messages.

For a code pair A,B, C is shared-group count and f(A),f(B) are group coverage. Attraction weight is Jaccard C/[f(A)+f(B)-C]. Three precomputed rules are available at minimum support 3 (default) and 2 (sensitivity view):

1. Shared-topic overlap: retain pairs sharing at least the chosen number of groups.

2. BY-enriched overlap: additionally retain a one-sided hypergeometric overlap tail with Benjamini–Yekutieli adjusted p ≤ 0.05. The fixed-margin reference distributes each code uniformly over groups with its coverage held fixed. Adjust across all pairs of codes eligible at that support before filtering support; this family is preserved in every bootstrap replicate. Topic richness, dependence and sequence are not preserved by that reference model, so this is a diagnostic rather than population inference.

3. Repeated message co-coding: require the pair to occur together in a message in at least the chosen number of distinct groups. Its weight remains topic-level Jaccard.

The support-3 and support-2 models are optimised independently, with respective eligible-code families of 132 and 224 codes. Community numbers are local to each rule and support level.

Leiden, layout and sensitivity

Weighted Leiden uses the RB configuration/modularity objective at resolution 1. The highest modularity result from 20 seeds is retained, starting at seed 20261008. Isolates remain outside community membership. Community numbers are ordered by size. Anchors are the three members with highest within-community weighted strength, then coverage and label. These are mathematical communities; qualitative interpretation still requires reading the messages and considering counterexamples.

The engine resamples the topic groups with replacement 50 times per model, rebuilds counts and weights, and reruns Leiden. Duplicate sampled groups count repeatedly. Co-assignment is conditional on both codes being present; ARI comparisons exclude reference isolates. Seed ARI and resolution sensitivity at 0.5, 1 and 1.5 are also retained. Bootstrap stability is an initial diagnostic, not a confidence interval or proof of a theme.

Community centres are spaced for navigation; weighted spring layouts use 400 iterations and a fixed seed inside each community. Node area reflects topic coverage with display limits. Screen edge and label budgets reduce clutter; all edges remain in the analysis and exported tables. Display distances between communities have no independent statistical meaning.

Animated build and outliers

The animation progressively ingests group-level incidence, updates counts and Jaccard weights, and runs the existing separate multilevel Louvain-style optimiser in JavaScript. It does not run Leiden in the browser or steer nodes to the fixed communities. At completed ingestion, supported weights agree with the Python reference. Positions and memberships may differ. Shuffled ingestion is a procedural sensitivity exercise, not chronological thematic analysis. The enriched replay uses final-archive BY-qualified edges as a declared eligibility gate.

Optional high-frequency outliers have no supported links in the selected model and at least the selected message floor (default 100, minimum 25). Hollow amber diamonds and dotted links to community topic unions are descriptive overlays. They do not change the partition or forces, and use the completed archive even during partial animation.

Technical depth and emotion

Profiles default to every captured message in the union of a community's associated topic groups; a selector restricts them to messages carrying a community descriptor. Messages are deduplicated within each profile, while profiles can overlap. The comparator is the full 5,000-message archive or all named-topic messages. Mean technical depth uses valid LLM scores 0, 1 and 2, with invalid values excluded and reported. Depth is descriptive and assumes equal spacing in an ordinal scale. Archive mean is 0.701600000 from 5,000 valid scores. Emotion and depth never determine network membership.

The existing platform-specific eleven-category emotion mapping and typo aliases are retained. Explicit previously recorded new-term mappings are also applied and reported below. Other unmapped terms remain unmapped; no new emotion assignments are invented. Category shares use the sum of nonneutral category-message counts, deduplicated within each message and category. Neutral, unmapped and multiple-category coverage are shown separately. The categories are a composition, not a psychological valence scale or measurements of internal mental states.

Recorded extensions applied: {"worried": {"category": "Disappointed", "basis": "Existing Decentraland mapping; provisional extension for Horizon"}}.

Files and reproduction

START_HERE.html compares the maps. FIXED_MAP.html and ANIMATED_MAP.html open each view directly. These are self-contained offline files. The map and profile buttons offer full screen and 6,000-pixel-wide PNG exports with complete code keys. Saved PNGs retain current rule, support and selected profile. analysis.json includes memberships, full edge data, topic incidence, record excerpts, source hashes and diagnostics. classification_snapshot.json records the all-main inclusion decision. CSVs contain communities and edges for all six models; default support-3 files have no prefix and support-2 files start support2_. Code_inventory.csv includes every descriptor; Code_memberships.csv lists its membership or unsupported status in every model.

Rebuild with: python build_analysis.py --root "<PhD workspace>" --bootstrap 50. Required Python packages are in requirements.txt; the supplied workspace also has work/gravity_runtime. Repackage existing analysis with python write_outputs.py. input_spec.json identifies the source and platform. The original manual and LLM sources are not edited.
